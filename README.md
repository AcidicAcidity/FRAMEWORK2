# Система совместного использования автомобилей

Приложение для каршеринга: владельцы регистрируют автомобили,
пользователи оформляют поездки. Предметная область представлена классами
`Car`, `User` и `Trip`, данные хранятся в JSON-файлах.

Консольная версия (ПР3) дополнена веб-интерфейсом на Django 5.2 (ПР5);
страницы формируются шаблонами Django (ПР6). В браузере можно
просматривать автомобили и поездки. Классы ПР3 и JSON-хранилище
используются веб-слоем как источник данных.

## Назначение
Платформа каршеринга (совместного использования автомобилей). Владельцы
сдают автомобили в краткосрочную аренду, пользователи быстро находят и
бронируют машину для поездки.

## Целевая аудитория
- Владельцы автомобилей — сдают автомобиль в аренду и получают доход.
- Пользователи (арендаторы) — берут автомобиль на короткое время.
- Администраторы сервиса — контролируют автомобили и поездки.

## Предметная область
Сервисы краткосрочной аренды транспортных средств (каршеринг), платформы
совместного потребления (sharing economy): регистрация автомобилей,
поиск доступных машин, оформление поездок и расчёт их стоимости.

Правила предметной области:
- на одну дату автомобиль может иметь только одну **активную** поездку;
- отменённая поездка не блокирует автомобиль и остаётся в списке;
- автомобиль с признаком `is_available = false` арендовать нельзя;
- скидка за длительность: 5% — от 6 часов, 15% — от 24 часов.

## Основные сущности

### Car — автомобиль
Атрибуты: `id`, `brand`, `model`, `number`, `owner` (объект `User`),
`price_per_hour`, `is_available`.

Методы и свойства:
- `calculate_price(hours)` — стоимость аренды со скидкой;
- `full_name` (`@property`) — марка и модель;
- `get_discount_percent(hours)` (`@staticmethod`) — размер скидки;
- `validate_price(price_per_hour)` (`@staticmethod`) — проверка цены;
- `__str__()` — строковое представление.

### User — пользователь (владелец или арендатор)
Атрибуты: `id`, `name`, `email`.

Методы:
- `from_data(data)` (`@classmethod`) — создание пользователя из словаря;
- `validate_email(email)` (`@staticmethod`) — проверка адреса почты;
- `__str__()` — строковое представление.

### Trip — поездка
Атрибуты: `id`, `car` (объект `Car`), `trip_date`, `user` (объект `User`),
`hours`, `is_cancelled`.

Методы и свойства:
- `cancel()` — отмена поездки (объект остаётся в коллекции);
- `price` (`@property`) — стоимость, рассчитанная автомобилем;
- `__str__()` — строковое представление с учётом состояния.

## Взаимодействие объектов
`Trip` хранит ссылки на объекты, а не идентификаторы:

    Trip
     ├── car  -> Car
     │            └── owner -> User (владелец)
     └── user -> User (арендатор)

Данные связанных объектов доступны напрямую: `trip.car.owner.name`,
`trip.user.email`. Стоимость поездки считает сам автомобиль:
`trip.car.calculate_price(trip.hours)`.

В приложении используются коллекции `list[Car]`, `list[User]`
и `list[Trip]`. Функции модулей работают с объектами; словари
применяются только при чтении и записи JSON (`storage.py`).

## Страницы веб-интерфейса
Маршруты двух уровней: `carsharing/urls.py` подключает `urls.py`
приложений через `include()`. У каждого приложения задан `app_name`
(пространство имён), поэтому ссылки строятся по именам вида `cars:list`.

| URL | Имя маршрута | View-функция | Шаблон |
|-----|--------------|--------------|--------|
| `/` | `homepage:index` | `homepage.views.index` | `homepage/index.html` |
| `/cars/` | `cars:list` | `cars.views.cars` | `cars/car_list.html` |
| `/cars/<int:car_id>/` | `cars:detail` | `cars.views.car_detail` | `cars/car_detail.html` |
| `/trips/` | `trips:list` | `trips.views.trips` | `trips/trip_list.html` |
| `/trips/<int:trip_id>/` | `trips:detail` | `trips.views.trip_detail` | `trips/trip_detail.html` |

Если автомобиль или поездка не найдены, view передаёт в шаблон `None`
и возвращает ответ со статусом 404 (`render(..., status=404)`), а
сообщение выводится в шаблоне через `{% if %}` / `{% else %}`.
Для адреса, которому не нашлось маршрута, срабатывает `handler404`
(`homepage.views.page_not_found`, шаблон `templates/404.html`).

Использование кода ПР3 в веб-слое: `load_users()`, `load_cars()`,
`load_trips()` (`storage.py`), `find_car_by_id()`, `find_trip_by_id()`,
`is_car_available()`, `Car.calculate_price()`, `Car.get_discount_percent()`.
Функции, изменяющие данные (регистрация автомобиля, оформление и отмена
поездки, поиск, фильтрация, сортировка), работают в консольной версии и
появятся в вебе вместе с формами и POST-запросами.

## Шаблоны Django (ПР6)
HTML в Python-коде больше не формируется: функция `page()` из ПР5
удалена, все view-функции используют `render(request, шаблон, context)`.
View получает данные ПР3 и передаёт их в шаблон через контекст, например
`{"cars": cars_list}`.

- **Базовый шаблон** `templates/base.html` — общий каркас (`<head>`,
  Bootstrap, собственный CSS, логотип, навигация, подвал, JavaScript) и
  блоки `{% block title %}` и `{% block content %}`. Каталог подключён в
  `settings.py` через `TEMPLATES["DIRS"]`.
- **Наследование**: дочерние шаблоны начинаются с
  `{% extends "base.html" %}` и переопределяют блоки.
- **Включаемые шаблоны** (`{% include %}`): `includes/navigation.html`
  (навигация), `cars/includes/car_card.html` (карточка автомобиля),
  `trips/includes/trip_status.html` (статус поездки; используется и в
  списке, и на странице поездки).
- **Циклы и условия**: `{% for %}` с `{% empty %}` для пустых списков;
  `{% if %}` / `{% elif %}` / `{% else %}` для статуса поездки,
  доступности автомобиля и страницы «не найдено».
- **Именованные URL**: ссылки строятся через `{% url 'cars:detail' car.id %}`;
  жёстко заданных адресов в шаблонах нет.
- **Фильтры**: `|length` (число автомобилей и поездок), `|default`
  (название автомобиля), `|date:"d.m.Y"` (дата поездки).
- **Автоэкранирование**: Django экранирует значения в `{{ ... }}`.

## Статические файлы
Находятся в `homepage/static/homepage/` и подключаются в `base.html`
через `{% load static %}` и `{% static %}`:
- `css/style.css` — собственные стили (`.car-card`, `.trip-status`,
  `.carsharing-logo`);
- `js/main.js` — подстановка текущего года в подвал;
- `img/logo.png` — логотип.

Проверка поиска файла: `python manage.py findstatic homepage/img/logo.png`.

## Основные операции
- автомобили: регистрация, просмотр, поиск, фильтрация по цене,
  сортировка по цене, проверка доступности на дату, расчёт стоимости;
- пользователи: добавление, просмотр, поиск по имени или почте;
- поездки: оформление, отмена, просмотр списка;
- статистика: число автомобилей, пользователей и поездок, выручка
  по активным поездкам.

## Хранение данных
Данные хранятся в каталоге `data/`:
- `users.json` — `id`, `name`, `email`;
- `cars.json` — `id`, `brand`, `model`, `number`, `owner_id`,
  `price_per_hour`, `is_available`;
- `trips.json` — `id`, `car_id`, `user_id`, `trip_date` (`ГГГГ-ММ-ДД`),
  `hours`, `is_cancelled`.

При загрузке данные из JSON преобразуются в объекты `User`, `Car`
и `Trip`: идентификаторы `owner_id`, `car_id`, `user_id` заменяются
ссылками на найденные объекты. При сохранении выполняется обратное
преобразование. Если файл повреждён или связанный объект не найден,
программа сообщает об ошибке и не затирает данные.

## Требования
- Python 3.11 (Django 5.2 требует Python 3.10+);
- Django 5.2, pytest, flake8.

Установка зависимостей:

    pip install -r requirements.txt

## Запуск программы
Веб-версия (Django):

    python manage.py migrate
    python manage.py runserver

Открыть в браузере http://127.0.0.1:8000/

Консольная версия (сохранена):

    python main.py

## Запуск тестов

    pytest -v                  # тесты предметной области (ПР3)
    python manage.py test      # тесты веб-страниц (ПР5)

Тесты проверяют создание и атрибуты объектов, `__str__`, методы классов,
поиск, фильтрацию и сортировку, правило доступности автомобиля, отмену
поездки, статистику и преобразование JSON <-> объекты.

## Текущее состояние и план развития
Реализовано:
- ПР5: Django-проект и приложения `homepage`, `cars`, `trips`;
  двухуровневая маршрутизация; динамические URL; страница 404;
- ПР6: шаблоны Django (`base.html`, `extends`, `block`, `include`),
  контекст, циклы и условия, именованные URL с пространствами имён,
  фильтры, собственные CSS, JavaScript и изображение.

Данные по-прежнему хранятся в JSON-файлах, Django ORM, база данных и
формы пока не используются — это задачи следующих работ.

Планируется:
- перенос `Car`, `User`, `Trip` в Django ORM и подключение базы данных;
- формы (регистрация автомобиля, оформление и отмена поездки);
- разработка API;
- контейнеризация приложения;
- настройка CI/CD.
